> CEO 2026-10-25 要求："盘点他的几个思路……从他的努力找到现在不方便接触网站内容的阻力点"。只记查到的事实，出处是仓库 README、docs/troubleshooting.md、docs/cloakbrowser.md、agent_reach/skill/SKILL.md、llms.txt、channels/web.py、runtime/public_web.py、CHANGELOG.md（2026-10-25 读的 main）。

## 一、它是什么

GitHub `Panniantong/Agent-Reach`，MIT，Python。2026-02-24 建，8 个月 10.2 万星、9 千 fork，Trendshift 单日第一。一句话：给 CLI Agent（Claude Code、Codex、OpenClaw 等）一条命令读 15 个平台（B站、小红书、推特、Reddit、YouTube、GitHub、V2EX、雪球、Boss、LinkedIn、小宇宙、Facebook、Instagram、网页）。只读不写。赞助商清一色是代理 IP 和抓取服务商（Bright Data、RapidProxy、BrowserAct、CoreClaw），说明它踩的是一个真市场。

## 二、它的思路（九条）

| # | 思路 | 它怎么做 | 对应的阻力 |
|---|---|---|---|
| 1 | 一条命令、一种出口 | `agent-reach <渠道> <动作>`，所有平台回同一形状的 JSON：`ok / items(title,url,author,published_at,text) / error(code,message,hint)`；错误码只有九个，每个带"下一步怎么办" | 每个平台形状都不一样，Agent 要为每家写一套；出错页是给人看的 |
| 2 | 每个动作一张"首选加备选"的有序工具表 | 读 B站先 bili-cli 再公开接口；读网页先 Jina Reader 再 Exa。平台改版只换表，Agent 用法不变 | 平台改版、工具失效是常态 |
| 3 | 公开优先，登录只在必要时 | 先用 Agent 自带搜索加 `site:` 限定；判定"页面壳、摘要、评论计数、字幕轨道列表不等于正文"；登录墙页算没拿到 | 登录墙；页面只渲染一个壳；摘要被当正文 |
| 4 | 专用隐身浏览器 | CloakBrowser 一份独立配置、无头、十分钟闲置自关；从用户 Chrome 只读复制该站登录态；用户本人登录，程序从不代登、不要密码；建议用小号 | 机器人指纹识别、验证码风控、自动访问账号被限、登录态管理 |
| 5 | 限流纪律 | 遇 `RATE_LIMITED / PLATFORM_BLOCKED / NEED_LOGIN / BUSY` 立即停，不换账号、不换后端、不反复重试；同平台最多 2 路、合计 4 路并发 | 平台惩罚重试和多账号 |
| 6 | 音视频转文字 | B站、YouTube 字幕；播客和视频走语音转写（Groq 或 OpenAI key）；yt-dlp 取流 | 内容锁在音视频里，模型读不到 |
| 7 | 中文平台单独做渠道 | B站、小红书、V2EX、雪球通用搜索覆盖差，各写适配器；提供 AtomGit 国内镜像；可配代理 | 搜索引擎覆盖不到；地区和网络封锁 |
| 8 | 自诊断 | `doctor / check`：每渠道状态 ready / needs_login / broken / regressed，24 小时内实测才算 ready；发版前记录真实验收（28/40 动作测通才发） | 坏了没人知道；"装好了"不等于"能用" |
| 9 | 让 Agent 自己装 | install.md 写成 Agent 可执行；根目录 llms.txt；技能文件一份真身、链接进多个 AI 的技能目录；不要管理员密码 | 工具装不上；文档不是给机器读的；技能被各家 AI 发现的方式不同 |

## 三、反过来看：Agent 接触网站内容的阻力点

按我们"六道门"归类（Agent 友好标准 v0.2 的底料）：

**进得去（门）**
1. 登录墙：正文、评论、字幕要登录才给。
2. 验证码与风控：识别出自动化就弹验证、封账号；平台对自动访问的账号另有限制。
3. 机器人指纹：普通无头浏览器被认出来，要专门的隐身浏览器。
4. 限流：频率一高就封；重试和换账号被加重惩罚。
5. 地区与网络：部分平台按地区拦；国内外互相够不着，要代理和镜像。

**看得懂（形）**
6. 内容不是文字：视频、音频、图片里的信息模型读不到，要字幕或转写。
7. 页面只有壳：靶内容靠脚本渲染或接口二次加载，抓到的是空页；摘要、计数、轨道列表被误当正文。
8. 没有机器可读的形状：每家字段不同，没有统一的"标题、链接、作者、时间、正文"。
9. 搜索覆盖不到：中文平台在通用搜索里几乎不可见，要进站搜。

**稳不稳（变）**
10. 平台说改就改：接口、页面、反爬一变，工具就死，要靠备选链和持续维护。
11. 登录态不可靠：过期、多处存储互相矛盾（Boss 的案例：本地凭据说已登录，浏览器其实没登录）。

**办得成 / 守规矩（规）**
12. 条款不允许自动化：它只敢只读，不发帖、不评论、不私信。
13. 密钥和密码没有给 Agent 的通道：只能用户本人在终端填，Agent 不许经手。
14. 工具装不上：权限、依赖、管理员密码；文档不是写给机器执行的。

它没碰的两道门：**能付钱**（Agent 自己完成支付和订阅）和**写操作的责任归属**。这两道正是我们标准里应该比它多出来的部分。

## 四、对我们的意思

- Agent Reach 是"绕路"：平台不友好，它替 Agent 翻墙过坎。我们要做的是"评路"：给平台打分，让平台自己修路。两件事互补，它的九个错误码和十四条阻力就是我们打分表的现成检查项。
- 它的输出契约（一种 JSON、九个错误码、每个带下一步）是"对 Agent 友好的接口"长什么样的现成样板，可以直接写进标准。
- 市场信号：8 个月 10 万星，赞助商全是代理和抓取商，说明"Agent 够不着网站"是真痛点、有真钱。评价体系站在它上游。
