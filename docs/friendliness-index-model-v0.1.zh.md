# 智能体友好指数模型 v0.1（打分版）· 2026-10-25

> 作者：OPC 维护团队（智能体辅助整理，经人核验）· 日期：2026-10-25

> **2026-10-25 CEO 定名**：官方叫"友好指数"（全称智能体友好指数）和"反智能体指数"，不叫"度"，"丝滑度"不用。下文"友好度"一律读作"友好指数"。

> CEO 2026-10-25 要："给我一个 Agent 友好度模型"。本文是打分模型；规则原文仍是我们的智能体友好标准 v0.1（内部文件，三层：找得到、读得懂、办得成），本文把它扩成六道门并给出分数。阻力点来源：`research-agent-reach-2026-10-25.zh.md` 十四条。

## 一、叫法

- 官方名：**友好指数**（全称智能体友好指数），配对的是**反智能体指数**（见 `anti-agent-index-model-v0.1.zh.md`）。CEO 2026-10-25 定："友好指数和反智能体指数吧，我们统一官方这么叫"。
- "度"不用，"丝滑度"不用（原先建议的对外小名作废）。
- 英文对应 agent-friendly / Agent Experience（AX）。

## 二、六道门与权重（满分 100）

| 门 | 权重 | 它回答的问题 | 检查项（每项 0 / 1 / 2 分，门内按比例折算） |
|---|---|---|---|
| 1 进得去 | 20 | Agent 能不能堂堂正正进来 | ① 有正门：API、MCP 或机器人账号 ② 条款允许自动化，写得明白 ③ 公开内容不登录就能读 ④ 正常频率访问不弹验证码、不风控 ⑤ 国内外都可达，或明说哪边不行 |
| 2 看得懂 | 20 | 拿到的是不是机器能读的内容 | ① 内容服务器端就出来，不靠脚本渲染 ② 有纯文本或 Markdown 版，或统一字段（标题、链接、作者、时间、正文） ③ 根目录有给机器的地图（llms.txt、sitemap、接口说明） ④ 音视频有字幕或文稿 ⑤ 出错信息是机器可读的码加下一步，不是一张给人看的页 |
| 3 办得成 | 25 | 标准任务能不能完成 | ① 标准任务完成率（见第三节任务集） ② 步数：Agent 完成一件事的步数不超过人的两倍 ③ 出错能恢复，不用从头来 ④ 有正式写入口（提交、下单、发帖）不靠模拟点按钮 |
| 4 稳不稳 | 10 | 今天能用，下月还能不能用 | ① 30 天内因平台改动导致的失败次数 ② 接口有版本号、弃用提前公告 ③ 限流可预期：返回还要等多久，而不是直接封 |
| 5 能付钱 | 10 | Agent 能不能自己花钱 | ① 能查价 ② 能在授权范围和预算上限内支付或订阅 ③ 账单机器可读 |
| 6 守规矩 | 15 | 出了事能不能说清谁干的 | ① 权限能收窄（只读、限范围） ② 操作有日志可审计 ③ Agent 身份能绑到真人或主体 ④ 密钥有安全通道，不经聊天窗口 |

等级：A 丝滑（85 分以上）、B 顺畅（70 到 84）、C 勉强（50 到 69）、D 不友好（50 以下）、X 拒绝（条款禁止自动化或正门为零，直接 X，不算分）。

v0.1 一套权重通用；评过十个平台后按类目（内容平台、电商、开发者平台、政务、工具）分别调权，调权要有数据。

## 三、怎么测（七步，每步留证据）

1. **定被测对象和类目**：一个平台一张卡；同类平台用同一套任务。
2. **标准 Agent**：固定一套（模型、harness、工具版本写进方法版本号），不用隐身浏览器、不用代理，就是普通 Agent 的样子。要换配置就升方法版本。
3. **标准任务集**（每类五件事）：找一条指定内容、读它全文、搜一个关键词、做一次写操作（发一条、下一单或提交一个表单，能回滚的）、查一次状态或账单。
4. **跑三遍录屏**：每遍记完成与否、步数、出错点、耗时。三遍取中位数。
5. **逐项打分带证据**：每个检查项一行，分数后面跟证据（截图、录屏时间点、接口返回原文）。没证据的分不算。
6. **算分出卡**：一份数据文件（见第四节）、一页文稿、一条视频；三者数字一致。
7. **公开方法、接受复测**：方法版本号和任务集公开，谁都能复测；被评方有异议按证据改分，改分留痕。复评每季一次，或平台大改后 30 天内。

## 五、先评自己

第一期先用这个模型评 OPC 自己的对外页面。既是示范，也顺手把模板做出来；评出来低分的地方就是我们自己先要修的。

## 六、两条底线

- **不收被评平台的钱**。收了评价体系就死。钱从 Agent 的主人（订阅榜单和数据）和想改进的平台的咨询那边来。
- **每个分都能复测**。国内评企业说错了算商业诋毁，所以没证据的分不发，方法公开。
