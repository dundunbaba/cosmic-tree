# 智能体友好度评估 skill（agent-friendliness-eval）v0.1

> 一句话：拿一个真实任务从头做到尾，记下中途不得不停下来让人动手的时间。人介入得越少、越短，这个东西对智能体就越友好。这是 MVP 的度量；六道门指数（`docs/friendliness-index-model-v0.1.zh.md`）仍是卡片上的正式指数，本 skill 的结果是它"办得成"一门的实测依据。

适用对象：网站、工具、命令行、API、MCP、一个多步工作流，任何智能体要用的东西。给谁用：任何智能体，任何运行时（Claude、codex、其他）；人照做也行。

## 零、底线（违反即作废）

1. **只探测不突破**：不绕验证码、不换 IP、不伪装身份、不用别人的账号。遇到验证码就停，记一次介入。
2. **诚实身份**：User-Agent 或账号说明里写明你是智能体（例 `my-agent/1.0 (agent; +联系方式)`）。
3. **不留凭据**：记录里不写账号名、token、key、密码、cookie。
4. **没证据的话不说**：每个结论后面跟原文、截图、返回体或日志行。

## 一、度量什么（MVP）

一次评估＝一个对象 × 一个任务 × 跑三遍。每遍记：

| 字段 | 意思 |
|---|---|
| `outcome` | 完成 / 部分完成 / 失败 / 未执行 |
| `total_minutes` | 从拿到任务到任务结束的总时长 |
| `steps` | 你实际发出的动作数（请求、点击、命令），不算思考 |
| `interventions[]` | 每次人工介入：在哪一步、为什么（登录 / 验证码 / 付费 / 授权 / 拍板 / 看不懂 / 出错恢复 / 其他）、人动手了几分钟 |
| `human_minutes` | 介入分钟之和（**只算人在动手或动脑的时间**） |
| `wait_minutes` | 等人回来的时间，另记，不算介入 |

三遍取中位数。衍生指标：完成率、介入占比（人工分钟 ÷ 总分钟）、每任务介入次数。

为什么是介入时间：它是智能体主人真正付出的成本，谁都能复刻、能跨对象比；比逐项打分少主观。

## 二、七步

1. **定对象与任务**。对象写名字、网址、类别（类别从 `baseline/README.md` 的类别表里选）。任务要是这个对象的**本职任务**，有明确完成判据（`done_when`）。标准任务集五件事任选其一或自拟：找一条指定内容、读它全文、搜一个关键词、做一次能回滚的写操作（发一条、提交一个表单）、查一次状态或账单。
2. **查基线库找对标**。打开 `baseline/sources.json`（或 `baseline/README.md` 的表），找同类别的源作对照组，记它们的 `id` 进 `baseline_refs`；核事实时优先引一级源，引三级源要再找一个源佐证。不用再满世界搜，这是基线库存在的理由。
3. **准备标准身份**。写明你的运行时、模型、工具版本；不用隐身浏览器、不用代理（用了就在 `notes` 写明，中国大陆可达性只认大陆网络下的实测）。
4. **跑三遍，边跑边记**。每遇到要人动手的地方就停表记一条介入事件：哪一步、原因、人花了几分钟；人不在就记等待。失败也记，写失败在哪一步。
5. **填记录**。照 `templates/run-record.json` 填成一个 JSON；证据（日志、返回体、截图）放在你自己的目录，`evidence[]` 里写清是什么、在哪。
6. **自检**。在宇宙之树仓根目录跑 `node scripts/check-run-record.mjs <你的记录.json>`，退出码 0 才算合格；它顺手算出中位数。
7. **提交**。到 https://github.com/dundunbaba/cosmic-tree/issues/new/choose 选"评估提交 · Evaluation submission"模板，贴记录 JSON 和一段结论。我们复核后：对象是已有卡的 → 写进卡的"我们的经验"或"办得成"；是新对象 → 建卡或进基线库候选；结论和我们不一致 → 走申诉改分，按证据改，改分留痕。国内访问 GitHub 不顺用 Gitee 镜像读，提交仍在 GitHub。

## 三、怎么写结论（对标链路）

一份评估至少说清三句：
- **和谁比**：同类别基线源里挑 1～3 个，列同一任务在它们那里要不要人介入（引基线库已有数据或你顺手跑一遍）。
- **差在哪一步**：对象比对标多出来的介入发生在哪一步、什么原因。
- **证据可信度**：引用的事实按基线库权威等级加权（一级 1.0、二级 0.7、三级 0.4）取平均，写一个 0 到 1 的数；全是你自己的实测就写 1.0 并给日志。

模板见 `templates/report.md`。

## 四、安装与复用

- Claude Code：把 `skills/agent-friendliness-eval/` 整个目录拷到 `~/.claude/skills/`（全局）或项目 `.claude/skills/`，然后 `/agent-friendliness-eval`。
- 其他运行时：把本文件当指令读，模板和校验脚本照用（脚本只要 Node 18+，零依赖）。
- 方法版本 `0.1`。换了度量或字段就升版本，老记录不改。

## 五、这个 skill 还不管的

- 不出六道门和六方面的分，那两份模型另有测法（`docs/`）。
- 不替平台做付费整改；不收被评平台的钱。
- 不评对象的内容好坏，只评智能体用它顺不顺。
