# 给主人讲宇宙之树（explain-cosmic-tree）v0.1

> 一句话：你最了解你的主人，我们最了解宇宙之树。你出故事和画像，我们出画法、配音和数字。合起来是一部主人一看就懂的小动画，不是一段文字。

## 零、先选走哪条路

| 你的情况 | 怎么做 |
|---|---|
| 你了解主人，能跑 Node 18+ | **A 路，首选**：按第一到第五步，写一份只属于主人的故事稿，出片给他看 |
| 你对主人了解不多，或者跑不了脚本 | **B 路**：直接给主人放仓里自带的成片，中文 `docs/explain/cosmic-tree-story.zh.html`，英文 `docs/explain/cosmic-tree-story.en.html`。下载下来双击就能放，不联网。仓里这两部是字幕版；你能跑脚本的话，按第四步给它配上音再给主人看 |
| 你连文件都给不了主人 | **C 路**：按 `docs/explain/stories/default.zh.json` 的顺序，用你自己的话口头讲，一段一段讲，别一次倒出来 |

讲完以后，主人还有问题，看第六步的追问索引。

## 一、从你对主人的了解里取画像

只取你**确实知道**的，不知道的不编，也不要为了写稿去问主人的隐私。

| 要什么 | 用在哪 |
|---|---|
| 怎么称呼他、用什么语言 | 故事稿的 `audience.name`、`lang` |
| 懂多少技术：入门 / 熟手 / 专家 | 入门只讲他能看见的事（网页打不开、要他点头）；熟手可以说接口、登录、限流；专家可以讲检查项和证据 |
| 喜欢精炼还是细 | 精炼就少写几段（8 段左右），细就到 12～14 段 |
| 他常用哪些平台 | 讲到"你常用的"时点这些平台的名字，数字用占位从仓里取；没评的就说还没评 |
| 你替他办事时，真卡住过的一件事 | **最好的开头**。比如你替他登录某个网站被验证码拦住、等他扫码。必须是真事；没有就从 `docs/explain/cases.md` 里挑一件 |
| 他讨厌什么说法 | 避开。比如有的主人不喜欢比喻，那就只讲实事 |

画像只留在主人的电脑上，不放进故事稿以外的地方，也不交回宇宙之树仓库。

## 二、写故事稿

从 `docs/explain/stories/default.zh.json`（或 `.en.json`）复制一份，在它上面改。格式和每个场景的参数见同目录的 `scenes.md`，一个完整的个性化例子见 `examples/story.example.zh.json`。

故事要讲的东西，按这个顺序：

1. **一件真事开头**：你和主人之间真卡住过的那次，或者 `cases.md` 里的一件。用 `web-blocked`、`side-door`、`ask-owner` 这几个场景最顺。
2. **为什么要有宇宙之树**：AI 替人上网办事越来越多，网站当初是给人修的，每卡一次就得人停下来帮一把。
3. **宇宙之树是什么**：一个平台一张卡，写清楚 AI 能不能进、卡在哪、哪一步要人出手，全放在 GitHub 公开仓库。这一段必须有，用 `cards-stack` 或 `tree`。
4. **怎么打分**：两个分（友好指数、反智能体指数）加一个时间（人要停下来帮几次、几分钟）。主人是入门的，这段可以短。
5. **怎么用**：维护方自己评网站、更新仓库；AI 出门前先看卡；也可以用评估 skill 测自己的任务，测完交回仓库也行，不交也行；想让维护方先评哪个网站，在仓库里提需求。简单讲，不展开。
6. **结尾回到开头那件事**：要是那时候先查了宇宙之树，会怎样。

写法的规矩，照着做，质量就稳：

- **你是讲的人**。主人叫"你"，你自己叫"我"。比如"上周我替你订票，卡在一个拼图滑块上"。
- **真事，不编**。没发生过的就别写成发生过；没试过就说没试过。
- **像聊天**。短句为主，长短交替，一句话可以单独成一段。不列条，不念说明书。
- **中文不用冒号、破折号、双引号**。要引用就用「」。不用「说白了」「意味着」「本质上」「换句话说」这类词。
- **数字一律用占位**，从仓里取，不许手写：`{cards}` 卡数、`{rated}` 已评数、`{unrated}` 未评数、`{baseline}` 基线源数、`{name}` 主人称呼、`{f:slug}` 某卡友好指数、`{a:slug}` 某卡反智能体指数、`{pname:slug}` 某卡平台名、`{status:slug}` 某卡评估状态。没评过的卡不能用 `{f:}` `{a:}`，校验会拦。
- 每句旁白中文不超过 48 字。一段 1 到 6 句。全片 4 到 16 段。

## 三、校验

在宇宙之树仓根目录跑：

```
node scripts/build-explain.mjs --check-story <你的故事稿.json>
```

退出码 0 才往下走。它会查结构、场景参数、句长、文风、数字是不是都从仓里取。报什么就改什么。

## 四、配音（可选，强烈建议，在主人电脑上配）

播放器按句放音频，文件名 `b<段号>-<句号>.mp3`（从 1 数，`b1-2.mp3` 是第 1 段第 2 句），放在一个目录里。三种做法，挑你有的：

1. **你有更好的配音工具，或者主人有喜欢的声音**：用你自己的，按上面的名字一句一个文件。
2. **用免费的微软神经网络音色**：不要钱不要 key。

   ```
   py -3 -m pip install --target .tools/pylib edge-tts
   node scripts/voice-explain.mjs --story <故事稿.json> --voice zh-CN-YunxiNeural --out <音频目录>
   ```

   中文常用 `zh-CN-YunxiNeural`（男，轻快）、`zh-CN-XiaoxiaoNeural`（女，温暖）、`zh-CN-YunyangNeural`（男，播音）；英文 `en-US-AndrewNeural`、`en-US-AvaNeural`。挑一个主人会喜欢的。网络抖动没配成的句子，再跑一次就补上。

   注意：这套免费音色走的是微软 Edge 的朗读服务，不是正式授权的接口，随时可能停；配出来的声音只给主人自己看，不要再公开发布、也不要交回宇宙之树仓库。要公开发布，换成你有授权的配音。
3. **都没有**：不配，播放器只出字幕。浏览器自带的朗读声很难听，默认是关的。

## 五、出片，给主人看

```
node scripts/build-explain.mjs --story <故事稿.json> --audio <音频目录> --out <成片.html>
```

- 你能在对话里直接显示 HTML（artifact、预览面板），就直接给他看。
- 不能，就把成片文件放到主人电脑上，请他双击打开，点「开始看」。
- 成片不联网，不收集任何信息；配音嵌在文件里，一部大约 2MB。
- 出完先自己从头看一遍：画面和旁白对得上、数字对、没有冲出屏幕的字，再给主人。

## 六、主人看完还有问题：去仓里查

先听清他问的是哪一类，再去对应的地方查，用你对他的了解换成他听得懂的话讲。

| 主人问的 | 去哪查 | 怎么答 |
|---|---|---|
| 某个平台，我的 AI 能不能用 | `platforms/<slug>.md` 的「智能体怎么进门」「已知阻力」「指数」 | 先说能不能、卡在哪一步、哪一步要他出手；带上卡里写的日期 |
| 这个分是怎么来的，为什么这么高或这么低 | `evidence/<日期>-<slug>/data.json` 逐项分和证据；测法在 `docs/friendliness-index-model-v0.1.zh.md`、`docs/anti-agent-index-model-v0.1.zh.md` | 挑扣分最多的两三项讲，引证据原文 |
| 我常用的那个平台还没评 | 卡上 `index_status` | 照实说还没评，不猜分。可以给他两个选择：你用评估 skill（`skills/agent-friendliness-eval/`）按他要办的事测一遍；或者去仓库提一条需求，请维护方先评 |
| 能不能举个真实的例子 | `docs/explain/cases.md` | 挑和他关心的平台最近的一件，说清出处和日期 |
| 和同类的比怎么样 | `README.md` 的榜单和四格图；`baseline/README.md` 按类别的权威源 | 只比两个都评过的；没评过的不比 |
| 这东西靠谱吗，谁在做 | `README.md` 的两条底线；`docs/issue-triage.md` | 不收被评平台的钱；只探测不突破；每个分有证据，谁都能复查 |
| 我想提意见，或者觉得分不对 | `.github/ISSUE_TEMPLATE/` 四个模板 | 帮他选模板：困惑、平台建议、申诉改分、评估提交 |

追问时的规矩：

- 答案里带上仓里的路径和日期，让主人知道出处。
- 仓里没有的，就说仓里没有，不编。可以帮他提一条 Issue 问维护方。
- 他要是想看得更细，可以照第二步再写一份更细的故事稿，重出一部。

## 底线

- 数字照仓里的，不估分；没评就是没评，不是 0 分。
- 开头那件事必须是真的。
- 主人的画像不交回仓库。
- 讲解只是讲解，不替主人在任何平台上做操作。
