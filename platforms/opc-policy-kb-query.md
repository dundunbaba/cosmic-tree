# 政策知识库查询页（OPC）

## 一句话
OPC 的一人公司政策知识库：国内一人公司、独立开发者和他们的智能体用的政策事实库，官方原文怎么说、出处在哪、哪天核的。只整理事实，不出法律意见，不提供 AI 问答。对外的查询页规划在 EdgeOne Pages 全球可用区（不含中国大陆），免费额度加访问键；到 2026-10-28 还没建，真源是 GitHub 私库。

## 智能体怎么进门
- 现在：没有对外入口。真源是私有仓库，不对外（2026-10-28 验）。
- 规划（访问层）：站点根放 `llms.txt`、`index.json`（全部条目的问题、主体、平台、动作、结论、风险、出处、核验日期）、每条一个 `.md`；之后只读 HTTP 接口按主体、平台、动作筛选和拿变更记录，访问键放请求头；键在持牌平台售卖，人工发放。

## 我们的经验
- 2026-10-17：CEO 定方向：不提供 AI 能力，只卖知识库访问；真源私库加付费访问键，另开公开仓放目录与样例获客（OPC 内部记录，2026-10-17）。
- 2026-10-18：按腾讯云备案助手口径核实：不备案只能选"全球可用区（不含中国大陆）"，默认子域名在大陆回 401 要绑自己的域名；个人备案的站不许登录、搜索、收费，所以查询页备了案也不能这样用（OPC 内部记录，2026-10-18）。
- 2026-10-19：收集程序上 NAS，每 6 小时查 33 个国内官方页，首轮 0 失败（OPC 内部记录，2026-10-19）。
- 2026-10-28：自评到场发现没有对外面可评，卡先占位，等 M4 查询页上线再评。

## 已知阻力
- 进得去：还没有门。上线后默认子域名大陆 401 的问题和游戏网页版一样，要绑域名。
- 看得懂：规划是纯 Markdown 加 index.json 加 llms.txt，方向对；上线后再验。
- 办得成：规划只读接口加访问键；写入口没有也不该有。
- 稳不稳：条目有核验日期和变更记录，这是它的卖点；待验。
- 能付钱：访问键在持牌平台卖、人工发放，智能体自己买不了，这是上线后最可能的低分项。
- 守规矩：访问键只读、按额度计次（已定，未实现）。

## 指数
准备评：没有对外面，不打分。等 M4 查询页上线后按 docs 两份模型和评估 skill 评；本卡 2026-10-28 建，证据目录 `evidence/2026-10-28-opc-policy-kb-query/` 只记"无对象"的核验（私库可见性）。
