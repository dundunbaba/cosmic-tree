# TikHub

## 一句话
第三方社媒数据接口服务：一个 key 覆盖抖音、TikTok、小红书、B站、微博、知乎、微信、快手等 16 个以上平台、1000 多个接口，按量计费加阶梯折扣，有 MCP 和 Python SDK。采集系统用它解析抖音，把"签名军备竞赛"交给厂商扛，和自己的账号解耦。

## 智能体怎么进门
- HTTP API 带 key；有 Python SDK、MCP 服务器，文档里甚至有给 Claude Code 的技能。
- 充值和余额在网页后台，要主人登录。
- 密钥纪律：key 只放本机加密文件和 NAS 密文目录，不进仓。

## 我们的经验
- 定位：采集系统"免费优先、TikHub 是唯一付费 API"的成本纪律；省事优先选 TikHub，省钱优先自建（OPC 内部记录，2026-10-25）。
- 2026-06 抖音转写全链闭环：TikHub 解析→无水印音频→ASR→摘要→入库，真机验通；"关注博主"功能用 TikHub 认创作者、拉作品列表、增量盯更新，请求预算、抖动、连续失败熔断写在配置里（OPC 内部记录，2026-06）。
- 账号安全：走 TikHub 不压平台账号，专用账号那套在此不适用；主人倾向第三方接口抓公开数据，与账号解耦零封号风险（OPC 内部记录，2026-10-25）。
- 2026-10：内部记录记 key 已存、账户余额待充（OPC 内部记录，2026-10）。
- 小红书接入预留了 tikhub_xhs 槽位，未实现（OPC 内部记录，2026-10-25）。

## 已知阻力
- 进得去：API 顺；余额用完就停。
- 看得懂：返回结构化 JSON。
- 办得成：只读，不做写操作。
- 稳不稳：上游平台改版由厂商追；我们这边余额没有自动告警。
- 能付钱：充值要人；按量计费。
- 守规矩：它抓的是平台公开数据，被抓平台的条款风险在它身上和用途上，评时要写清。
